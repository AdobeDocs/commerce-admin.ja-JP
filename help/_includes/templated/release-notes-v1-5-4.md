# Adobe Commerce B2Bで修正された問題（v1.5.4-alpha1）

## B2B v1.5.4-alpha1

*2026年10月13日*

Adobe Commerce B2B 1.5.4-alpha1 コードでは、23の問題が修正されました。 このリリースに含まれる修正された問題のサブセットについて、以下で説明します。

### 管理者UI

#### [B2B] バックエンドの見積もりで価格を更新した後、バンドル製品の数量が保持されない

設定ダイアログで設定変更を行った後、グリッド内の数量を編集した後、管理者交渉可能な見積もりのバンドルアイテムの数量が以前の値に戻る問題を修正しました。

_ACP2E-5005_

### B2B

#### [B2B]見積もり詳細ページ （ストアフロントおよび管理者）は、関連製品がカタログから削除されると、アイテム/製品情報を失います

最終交渉可能な見積もりから販売不可の製品が消える問題を修正しました

_ACP2E-4680_

#### バックエンドから見積もりを送信した後、バンドル製品数量が正しく更新されない

管理パネルから交渉可能な見積もりを再設定する際に、バンドル製品オプションの数量が更新されない問題を修正しました。 以前は、「設定」ボタンを使用してバンドルオプションの量に加えた変更は、サイレントに破棄されていました。

_ACP2E-4801_

#### [CLOUD] [B2B]管理会社グリッドが原因で高いMySQL CPU – 相関するcompany_type / COUNT クエリ

管理会社グリッド（お客様→会社）でMySQL CPUの使用率が高く、データベースのセッションが長時間実行される問題を修正しました。 以前は、各行の会社タイプ（親/子/会社）を決定するには、会社の行ごとに1回実行されるcompany_relation テーブルに対する相関サブクエリが必要でした。リスト数クエリと合計数クエリの両方をO （N²）で大規模に実行します。この修正により、データセットのサイズに関係なく1回実行される単一の事前集約されたJOINに置き換わります。

_ACP2E-4846_

#### アカウントでの支払い（B2B） - COD用に表示されている間、保留中の注文に対して「注文を編集」ボタンが表示されない

「注文を編集」ボタンが、アカウントに支払いが発生した注文で使用できるようになりました。 以前は、注文が保留中の間に支払い口座に入った注文を編集することはできませんでした

_ACP2E-4877_

#### 複数の会社のスーパーユーザーを使用してB2B企業を節約するPHPのタイムアウト

B2B会社を保存したり、会社のスーパーユーザーページを管理者に読み込んだりしても、会社のスーパーユーザーが非常に多くの会社に割り当てられている場合に、PHPの最大実行時間を超えなくなりました。

_ACP2E-4967_

#### [ON-PREM]交渉可能な引用符が期待どおりに更新されません

アクティブな交渉可能な見積に存在する製品が削除されたときに、交渉可能な見積が更新されない問題を修正しました。

_ACP2E-5001_

#### Volatile &#39;Payment on Account&#39;追加チェック

B2B企業のメンバー専用の支払い方法である「アカウントでのお支払い」が、チェックアウト時に個人（B2C）のお客様によって選択される問題を修正しました。 以前は、このような顧客が「支払い方法が利用できません」というエラーを受け取る代わりに、アカウントでの支払いを続行することが誤って許可されていました。

_ACP2E-5013_

#### 共有カタログ ウィザードの保存アクションにより、共有カタログの価格構造が消去されます

共有カタログウィザードの保存アクションによって、共有カタログ保存の価格構造が消去される問題を修正しました

_ACP2E-5015_

#### GraphQL customer.roleが、会社を持たないB2Cのお客様に「内部サーバーエラー」を返す

GraphQLを介してcustomer { role {...} }に問い合わせると、どの企業にも割り当てられていないB2Cのお客様に対しても「内部サーバーエラー」が返される問題を修正しました。 以前は、このクエリは、nullの会社IDが厳密な整数型ヒントを持つメソッドに渡されたため、PHP TypeErrorをトリガーしました。

_ACP2E-5017_

#### [B2B] バックエンドの見積でオプションの数量が更新された場合、バンドル製品品目割引は適用されません

バックエンドの見積もり管理画面で動的価格バンドル製品に適用されたアイテムレベルの割引が、小計または小計（除く）に反映されない問題を修正しました。 「税金」）列は、設定ダイアログでバンドルのオプション数量が更新されたときに表示されます。 以前は、割引は割引列に表示されていましたが、見積もられた小計は減少しませんでした。

_ACP2E-5034_

#### すべてのページナビゲーションでリクエストセクションが再読み込みされる

すべての製品およびカテゴリページナビゲーションで、要求セクションが不要なAJAXのリロードをトリガーする問題を修正しました。 以前は、このセクションは、変更が行われていない場合でも、空でない要求リストデータを持つ任意の顧客のページ読み込みごとに再読み込みされていました。

_ACP2E-5037_

#### 会社の住所に地域データが見つからないときに[B2B] エラーが発生しました

会社プロファイルページと管理者顧客編集ページで、住所が地域なしで保存された後に、会社の住所に地域が追加された場合にエラーが表示される問題を修正しました。 これで、アドレスはエラーを引き起こす代わりに、格納された地域テキストに正しくフォールバックされます。

_ACP2E-5092_

#### 英語以外のロケールリセットのクレジット制限を持つ管理者の会社アップデート

管理者のロケールがデフォルトのロケールと異なる場合に、B2B会社の詳細を編集すると、設定されたクレジット制限が誤って0にリセットされる可能性がある問題を修正しました。 クレジット制限は、明示的に変更されない限り、正しく保持されるようになりました。

_ACP2E-5127_

#### [CLOUD] Web サイト制限付き管理者は、ユーザーIDがアクセスできない顧客entity_idと競合する場合、顧客を削除できません

以前、web サイト制限の管理者が顧客を削除しようとすると、システムの権限チェックプラグインは、管理者のユーザーIDと比較されました
顧客エンティティ IDを使用して、会社階層の制限を適用します。アクションを行うユーザーが実際に顧客であることを確認する必要はありません。管理者のユーザーIDが発生した場合
管理者がアクセスできなかったweb サイト上の無関係な顧客のエンティティ IDと一致させるために、プラグインはそのアクセスできない顧客レコードを読み込もうとしました
管理者が削除する顧客に対する有効な権限を持っていても、「その他の権限が必要です」というエラーが表示され、削除は失敗しました。 この問題は解決済みです
customer-IDの比較を実行する条件を追加することで、アクションを行うユーザーが本当に顧客である場合にのみ実行されます。つまり、管理者が開始した削除は、そのチェックを完全にバイパスするようになりました。制限付き管理者は、関連のないアクセスできない顧客レコードによってブロックされることなく、割り当てられたweb サイト内の顧客を再度削除できます

_ACP2E-5146_

#### 管理者販売注文でB2B注文に誤った会社名が表示される

ユーザーが複数の会社に割り当てられたときに、管理販売注文でB2B発注に間違った会社名が表示される問題を修正しました。
注文に関連付けられている会社に基づいて、会社名が正しく表示されるようになりました。

_B2B-4656_

### B2B、カート、チェックアウト

#### [ON PREM] [B2B] .CSV拡張子で終わるバイナリファイルをアップロードしようとすると、クイックオーダーのアップローダーがフリーズする

クイックオーダーのファイルアップローダーが、バイナリを含む.csv拡張子で名前が変更されたファイルを受け入れた問題を修正しました。 以前は、MIME タイプやコンテンツの検証は実行されていなかったため、CSV以外のファイル（実行可能ファイルなど）を、有効なSKU/QTY リストであるかのようにアップロードおよび処理することができました。

_ACP2E-5212_

### B2B, GraphQL

#### 要求リスト GQL合計数の不正確さ

requisition_lists GraphQL クエリで、クエリ条件に一致する購買リストエンティティの合計数ではなく、現在のページの項目数のみを反映する誤ったtotal_count値が返される問題を修正しました。

_ACP2E-4799_

### B2B，注文

#### 5900万以上の見積もりテーブルのクリーニングに関するヘルプ （sales_clean_quotesを実行できません）

`sales_clean_quotes` cron ジョブが大きな見積もりテーブルを含むインスタンスでタイムアウトする問題を修正しました。 以前は、クリーンアップクエリで`negotiable_quote` テーブルのすべての列が不必要に選択されたため、MySQLは数百万行に対して完全なファイルソートを実行し、各引用符はPHP モデルレイヤーを介して個別に削除され、パフォーマンスコストが増大しました。

_ACP2E-4891 - [GitHub コードの貢献度](https://github.com/magento/magento2/commit/b63925d9)_

### B2B, パフォーマンス

#### [CLOUD] ACSD-70033：テーブル magento_catalogpermissions_index_productのデッドロックのフォローアップ。 続き

以前は、共有カタログを有効にしてカタログ権限を再インデックス化すると、デッドロックエラーが発生し、再インデックスが失敗する可能性がありました。 複数のインデクサープロセスが同時に実行される場合でも、インデックスの再作成は正常に完了します。

_ACP2E-4844_

### コンテンツ

#### 異なるweb サイト用に作成されたCMS ページで、フロントエンドに間違ったページが表示される

以前は、Web サイト制限ランディングページのキャッシュキーがweb サイトごとにスコープされていない複数のweb サイト設定では、セカンダリ web サイトのストアフロントで間違ったCMS ページが提供されていました。 WebsiteRestriction/Controller/Index/Stub.phpのキャッシュキーに、ストアマネージャーで解決された現在のweb サイト IDが正しく含まれるようになりました。

_ACP2E-4593_

### フレームワーク

#### [B2B]発注がActiveMQで販売注文に自動変換されない

ActiveMQをSTOMP プロトコルで使用した場合に、cronで開始されたコンシューマーがメッセージを処理しない問題を修正しました。 その結果、自動承認済みの発注は受注に変換されませんでした。 STOMP キューのメッセージ処理が、DBおよびAMQP キューの実装に対してより信頼性が高く、一貫性を持つようになりました。

_ACP2E-4349 - [GitHub コードの貢献度](https://github.com/magento/magento2/commit/08b91f1a) - [GitHub コードの貢献度](https://github.com/magento/inventory/commit/239464da)_

### インストールと管理

#### [Cloud]古い既存のISO再分割コードの修正

13か国の地域コードを更新し、ISO 3166-2標準に一致しました。 以前は、一部の地域コードが標準に一致しなかったため、サードパーティの統合や国際的なコンプライアンスに問題が発生する可能性がありました。 ベルギー、コロンビア、スペイン、フランス、イタリア、ラトビアに新しい地域が追加されました。 オーストリア、コロンビア、コスタリカ、ドイツ、エストニア、スペイン、フィンランド、フランス、インド、アイスランド、ラトビアの地域コードが更新されました。

_ACP2E-4495 - [GitHub コードの貢献度](https://github.com/magento/magento2/commit/9b6a8bd9)_
